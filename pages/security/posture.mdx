# Security posture

<Callout type="warning">
**We are not SOC 2 certified.** We run a strong technical posture, our data lives in SOC 2-compliant infrastructure (Supabase / AWS), and we have the engineering controls in place. We have not yet engaged a SOC 2 auditor and do not have a Type I report. We're being explicit about this rather than implying otherwise.
</Callout>

## In production today

Every item below is shipped, in code, on production. No marketing fluff.

### Row-level security on every table
Postgres RLS policies on every customer-facing table — `rolls`, `jobs`, `purchase_orders`, `cut_history`, `audit_log`, `notifications`, and 12+ others. No app-layer bypass. If the JWT cannot see it, the database refuses to return it.

### Six-role RBAC, enforced twice
The role matrix (`super_admin`, `admin`, `manager`, `operator`, `viewer`, `customer`) is enforced both in Next.js middleware (defense in depth) and in RLS policies (the database is the last line of defense). Either layer alone is sufficient — together they are redundant by design.

### Admin audit log
Sensitive admin actions write to an `audit_log` table with `before_value` and `after_value` JSONB snapshots, IP address, and user agent. Field-level changes captured. The audit log is itself RLS-protected; only `super_admin` can read it.

### Security headers middleware
Every response carries:
- `Content-Security-Policy` (strict, with explicit allowlists per asset type)
- `X-Frame-Options: DENY`
- `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `X-Content-Type-Options: nosniff`

### Signed-URL document sharing
Customer-facing PDFs (job receipts, invoices) use signed Supabase Storage URLs, not public-by-default access. Cut-history layouts and operator notes never leave the firm without an explicit export action by a manager+ role.

### Authentication via Supabase, MFA-capable
JWT auth with refresh-token rotation. Secure HTTP-only session cookies. MFA is supported and can be enforced for admin and manager roles via the workspace settings.

### Encryption at rest
Database and object storage are encrypted at rest by default via Supabase + AWS KMS. TLS 1.3 in transit.

## Not yet in production

If a security questionnaire is asking about any of these, the answer is "not yet, here's the timeline" — see the [SOC 2 roadmap](/security/soc2-roadmap).

- **SOC 2 Type I or Type II certification** — no auditor engaged yet
- **Formal security policy and risk register** — codified policies, training records, vendor-risk scoring
- **External SIEM / log aggregation** — audit log is currently Postgres-only; long-term retention pipeline pending
- **Forced MFA across the org** — supported but not currently enforced as a hard requirement
- **Third-party penetration test** — will be commissioned as part of SOC 2 prep
- **Field-level encryption beyond Supabase default** — not yet
- **Formal incident response plan** — drafted, not yet exercised
- **Vulnerability management program** — `npm audit` and `cargo audit` not yet wired into CI gates
